## Key decisions & rationale
- Split the C++/Python responsibilities so the outer sweep (which test points, which
  partition ratios, upstream findings lookup) lives in Python (`sweep.py`), while the CUDA
  binary measures exactly one cell. This is a deviation from Phase 1's style (which did
  its whole sweep inside the C++ binary) — necessary here because the sweep depends on
  values read from JSON at run time (test point sizes from Phase 2, tpb/blocks from
  Phase 1), and JSON parsing plus the TODO-placeholder fallback logic is far simpler in
  Python. `derive_findings.py` and `plot.py` still follow Phase 1's pattern exactly.
- `delta_vs_shared_pct` is computed in `sweep.py` after collecting all cells for a test
  point (not inside `phase3_bench`, which only sees one cell at a time and has no way to
  know the sibling shared-baseline value).
- Green context driver-API call sequence (`cuDeviceGetDevResource` ->
  `cuDevSmResourceSplitByCount` -> `cuDevResourceGenerateDesc` -> `cuGreenCtxCreate` ->
  `cuCtxFromGreenCtx` -> `cuGreenCtxStreamCreate`) was written from memory against the
  documented CUDA 12.4 API and is **unverified against a real `<cuda.h>`** — flagged
  prominently in the README and file header comment, consistent with the prompt's
  "first verify the API ... if not, stop and report" instruction.
