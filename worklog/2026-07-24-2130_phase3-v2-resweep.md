## Key decisions & rationale
- **Block search lower bound scales with assigned SM count via
  `max(phase1_seed, 4 * assigned_sm_count)`**, not the phase1 seed alone -- per the prompt's
  explicit instruction that the search range must scale with the partition's own SM count,
  and 4 blocks/SM matches Phase 1's own ~64-blocks/16-SM ratio at its saturation point.
- **Regime classification uses a fixed `PARTITION_SM_REF=8`**, not the actual best-found split
  for that point, specifically to avoid circularity (regime must be a property of the size,
  independent of whether green won there) -- documented at length in
  `derive_findings.py`'s module docstring and `README.md`'s Design notes, since this is a
  deviation from the v1 script's (backwards) approach and future sessions should not "fix" it
  back.
- **The Change-1 sanity gate reads Phase 2's raw results CSV** (via the path in its
  `findings.json`'s `source_csv` field), not just its `findings.json`, because Phase 2's
  `findings.json` only stores `scaling_efficiency` for the onset point, not the raw GB/s the
  v2 prompt's sanity gate needs. This is a new upstream read not present in the original
  Phase 3 harness; documented in README's "Dependency on upstream findings" section so it
  doesn't look like an accidental convention violation.
- **v1's 135.512 GB/s reference is a hardcoded, documented constant** in
  `derive_findings.py`, not read dynamically, because this script's own run overwrites the CSV
  that number came from. This is the one deliberate exception to "never hard-code, always
  read" in this session's work; the constant is named and comment-sourced so it doesn't read
  as fabrication.
- **Did not overwrite the committed v1 `results/`, `findings.json`, `FINDINGS.md`.** I have no
  CUDA device in this session, so I cannot produce real v2 measurements. Overwriting them with
  synthetic/placeholder numbers would violate "never fabricate" (00_conventions.md #2) even
  though the prompt says this run "supersedes" v1 -- superseding requires an actual re-run.
  Left a clear Status section in README instead.
