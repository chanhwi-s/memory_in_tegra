## Summary
Fixed the green-context SM partitioning in `phase3_bench.cu` after the first on-device run
threw `CUDA_ERROR_INVALID_RESOURCE_CONFIGURATION` for every green cell (even 8:8). Root
cause: the two partitions were created via two separate `cuDevSmResourceSplitByCount`
calls; the Tegra driver requires both to come from a SINGLE split call (`result[0]` +
its `remaining` output). Also made `run.sh` a full single entry point (sweep -> plots ->
findings in one command).

## What I did
- Rewrote the partition helpers in `src/phase3_bench.cu`:
  `trySplitAndMakeTwoPartitions()` does one `cuDeviceGetDevResource` + one
  `cuDevSmResourceSplitByCount(result, &nbGroups, &sm, &remaining, 0, minCount)`; green
  ctx 0 is built from `result[0]`, green ctx 1 from `remaining` (each via
  `cuDevResourceGenerateDesc` + `cuGreenCtxCreate` with `CU_GREEN_CTX_DEFAULT_STREAM`).
  The ratio is now swept by varying `minCount` (= sm0) only; partition 1 automatically
  gets `16 - sm0` SMs.
- Enforced Tegra's rule that `minCount` must be a multiple of 2 (validated in `main()`
  before any driver call).
- Every driver call's return code is now checked individually; a rejected/invalid ratio
  exits with code 4 (new) instead of aborting. `scripts/sweep.py` treats rc=4 as
  "warn + skip this cell, continue the sweep"; other nonzero codes still abort.
- `sweep.py` asymmetric ratio generator now rounds to the nearest even SM count.
- `scripts/run.sh` now calls `plot.py` and `derive_findings.py` after the sweep +
  `--verify` step, so one `run.sh` invocation produces CSV + verification + plots +
  findings.json/FINDINGS.md (user-requested workflow standard for all future phases).
- Updated README (Status + Design notes) to document the single-split-call requirement
  and the exit-code-4 skip contract; removed stale "never compiled" caveats since the
  binary now builds and runs on-device.

## Key decisions & rationale
- Exit code 4 = "this ratio invalid, skip" is a soft failure distinct from rc 3
  ("API unavailable", still fatal for green cells) so the sweep survives a driver
  rejecting one ratio without masking real failures.
- `--sm1` is still accepted on the CLI but only as a consistency check
  (`sm0 + sm1 == 16` enforced), since the remainder partition's size is no longer an
  independent choice.
