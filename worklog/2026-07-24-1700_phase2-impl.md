## Key decisions & rationale
- **Reuse fixed at N=1, not swept** — the prompt's "Swept axes" section for Phase 2 only lists
  size (2a/2b); the CSV schema it specifies has no `reuse_N` column. Deviates from Phase 1 (which
  does sweep reuse) intentionally, per the prompt as written.
- **`single_k*_GBps_ref` sourced from Phase 1's raw CSV, not re-measured in-process** — Phase 1's
  `findings.json` only carries summary tier numbers (no per-size throughput curve), so the ref
  values needed for `scaling_efficiency` are read from `phase1_results.csv` directly (read-only,
  doesn't violate the phase-isolation write rule). A separate in-process isolated measurement is
  also done, but only as an overlap sanity check — kept conceptually distinct from the Phase-1
  baseline per `00_conventions.md` #2 ("never... re-derive them").
- **Block-count search simplified to two 1D passes** instead of a full 2D (K0 blocks × K1 blocks)
  grid, to keep the per-cell search cheap. Documented as a simplification in README; may miss a
  joint optimum in principle.
- **Fallback config when Phase 1 findings are absent**: `gen_config.py` still produces a full
  sweep plan using OVERVIEW.md's documented tier placeholders and `-1` reference throughput (so
  `scaling_efficiency` becomes `-1`, clearly a sentinel, never a fabricated ratio). This matches
  the prompt's explicit allowance ("You may implement the full harness... independently of
  Phase 1... expose those as CLI/config parameters with sensible placeholder defaults").
